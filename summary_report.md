# Summary Report — Deep Learning Practical Exam Set C

## Tasks and datasets

This practical contains five small projects covering different deep-learning and computer-vision techniques. The ANN task uses scikit-learn's Wine Recognition dataset, containing 178 rows, 13 chemical features and three wine classes. The OpenCV task processes five images: four built-in `scikit-image` images (astronaut, coffee, chelsea and rocket) plus a flower image. It demonstrates resizing, HSV conversion, red-colour masking, morphology, Sobel edge detection and Haar-cascade face detection. The CNN task uses a subset of MNIST with 20,000 training images and 4,000 test images. The recurrent model uses the Melbourne daily minimum-temperature series to predict the next day from the previous 30 days. The Transformer task uses five short India-related paragraphs and pretrained Hugging Face pipelines for fill-mask, question answering and text generation.

## Results from the included sample notebook run

The ANN reached a test accuracy of **94.44%** on the Wine dataset. This is a useful result for a small tabular dataset and demonstrates why feature scaling and a Softmax output are appropriate for multi-class classification. The OpenCV workflow processed all five images and produced a 5-by-5 processing grid plus face-detection images; detections depend on the image and Haar-cascade settings. On the MNIST subset, the CNN reached **97.55%** test accuracy in the sample run. The CNN's convolution and pooling layers preserve and learn local image patterns, while the ANN baseline operates on flattened pixels. The GRU temperature forecaster reported a sample RMSE of **2.23 °C**. The notebook also calculates a naive persistence baseline so the GRU can be judged against a simple prediction strategy. For the question-answering task, **7 of 10** responses were manually marked correct in the included run. The model sometimes returns a plausible answer even when the paragraph does not contain the answer, which illustrates why confidence scores are not proof of correctness.

These numbers are copied from the example notebook's recorded run and are not guaranteed to repeat exactly on another machine. Transformer model downloads require internet access, and training results can vary by software version and runtime.

## Learning and next steps

The most useful lesson is that each architecture is suited to a different kind of input: dense layers for tabular features, convolutional layers for spatial image patterns, GRUs for ordered time-series data, and Transformers for contextual language tasks. I also learned the importance of avoiding data leakage by fitting scalers on training data only and preserving time order when splitting a time series. The CNN's shared convolution filters provide a useful inductive bias for images and can achieve strong accuracy without treating every pixel as an unrelated input feature. A GRU processes sequence steps recurrently, whereas a Transformer uses attention to connect tokens or positions directly. A GPT-style model may generate fluent but incorrect statements, so a real application should add source grounding, validation, refusal handling and human review for high-impact outputs. Haar cascades remain useful for lightweight, fast face detection in constrained environments, though they are less robust than modern learned detectors.

With more time and compute, I would tune the architectures with a validation strategy, compare the GRU with an LSTM and stronger forecasting baselines, test image processing under varied lighting, and add automated evaluation for Transformer outputs. I would also run the notebook from a clean environment, verify every generated artifact, and publish the final models and a short face-and-screen demonstration video.
